Notion Agency Client Portal Architecture: Six Databases That Need Relationships

A strong agency portal is not a folder tree with nicer colors. It is a set of related records that can answer operational questions quickly.

A practical six-part model

  1. Clients
  2. Projects
  3. Tasks
  4. Deliverables
  5. Meetings / Decisions
  6. Commercial / Invoices

The exact names can change, but the relationships matter: every task should belong to a project, every project to a client, and every deliverable should be traceable to the work that produced it.

Design for the view, not only the database

Clients want clarity. Operators want filtering and history. Build views around those questions rather than exposing every internal property.

What to avoid

  • duplicate client records;
  • free-text fields where a relation is required;
  • critical status information stored only in page titles;
  • workflows that require manual copying between databases.

Commercial value

The paid asset should package a reusable relational schema, setup manual, formulas, prompts and the rules for creating a clean client portal—not merely a screenshot.
